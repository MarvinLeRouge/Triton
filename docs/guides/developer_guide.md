## API reference

- REST: interactive Swagger UI generated by FastAPI, served at `/docs`
  (e.g. `http://localhost:8000/docs`, or `.../api/docs` behind Traefik).
- WebSocket (`/ws/game`, not covered by Swagger): the server sends a JSON
  payload on connect and after every subsequent turn, shaped like
  `Simulation.to_dict()`:

  ```json
  {
    "turn": 12,
    "result": "in_progress",
    "mothership": { "row": 10, "col": 4 },
    "drones": [
      {
        "row": 8, "col": 6, "heading": [1, 0],
        "detection_state": "searching",
        "strategy": "greedy_max_probability"
      }
    ],
    "vessel": { "row": 20, "col": 30 },
    "detection_events": [],
    "probability_map": [[0.001, 0.002, "..."], "..."]
  }
  ```

  `result` is one of `in_progress`, `blue_wins`, `red_wins`. The connection
  is one `Simulation` per socket — there is no request the client can send
  back yet (playback controls are planned for Phase 7).

## Plugging in a new algorithm

The engine is designed so new decision logic can be added without touching
`Simulation`'s turn loop.

### A new search strategy (how drones search)

Implement `SearchStrategy` (`engine/search_strategy.py`):

```python
class MyStrategy(SearchStrategy):
    @property
    def name(self) -> str:
        return "my_strategy"  # stable id, exposed to the API/frontend

    def next_target(
        self, position: tuple[int, int], speed: int,
        grid: Grid, probability_map: ProbabilityMap,
    ) -> tuple[int, int]:
        ...  # return the (row, col) cell to move to this turn
```

Add an instance of it to the pool passed into `StrategyAssignment` when
constructing a `Simulation`. Each drone independently rolls a chance to
switch to a randomly picked strategy from that pool every turn
(`StrategyAssignment.advance()`), so a new strategy just needs to be in the
pool to start being used — no other wiring required.

### A new Red behavior (evasion, movement)

Red's behavior lives in `engine/red_behavior.py` as plain functions
(`red_baseline_target`, `red_evasion_target`, `blue_units_within_range`)
rather than a strategy interface, since Red has a single, deterministic
decision process (not a rotating pool). Add a new function following the
same signature shape (current position, blue positions/threat info, grid →
next target) and call it from `Simulation`'s Red movement step in place of
(or in addition to, behind a condition) the existing one.

### A new sonar detection law

`SonarModel` (`engine/sonar_model.py`) encapsulates the cone geometry and
the probability-of-detection law as one class. To try a different law
(e.g. a different decay function, a different cone half-angle), either
change its internals directly or introduce a second implementation with the
same public surface (`range_cells`, the detection-probability method) and
inject it wherever `Simulation` is constructed.

## Testing conventions

Mirror the source structure under `tests/engine/`, `tests/api/`,
`frontend/src/**/__tests__/`. TDD (red-green-refactor) is the expected
workflow for engine and API changes.
